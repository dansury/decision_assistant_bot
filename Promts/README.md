# Promts — промты слоёв многослойного анализа

Один файл = один слой (или под-слой) конвейера из [`ТЗ.md`](../ТЗ.md) §5.
Каждый файл имеет одинаковую структуру: **Роль / Вход / Обязанности / Формат
вывода / Запреты**. Это не «системный промт целиком», а модуль — сборка в
итоговый `system_prompt` агента делает `docker/entrypoint.sh` (порядок сборки
ниже совпадает с порядком таблицы, слои со звёздочкой подключаются только
когда роутинг слоя 0 их выбрал — см. `00_router.md`).

## Порядок сборки системного промта

1. `00_router.md` — всегда
2. `01_transcription_cleanup.md` — только для голос/видео (*)
3. `02_entity_recognition.md` — всегда, если в тексте есть упоминания людей
4. `03_classification.md` — всегда
5. `04a_extract_decision.md` … `04e_consultant_synthesis.md` — только если
   слой 3 классифицировал запись как `decision` (*)
6. `04f_decision_outcome.md` — только если слой 3 классифицировал запись
   как `outcome` — пользователь сообщает исход прошлого решения (*)
7. `05_document_intake.md` — только для документов (*)
8. `06_photo_people.md` — только для фото с людьми (*)
9. `07_handwriting.md` — только для фото с рукописным текстом (*)
10. `08_obsidian_lint.md` — всегда, последний шаг перед записью
11. `09_feedback_and_model_switch.md` — всегда, определяет формат ответа и
    обработку 👍/👎
12. `10_history_import.md` — только при подключении нового источника или
    просьбе прочитать историю канала/группы целиком (*)
13. `11_archive_ingest.md` — только когда владелец прислал zip-архив
    (экспорт переписки/канала или Obsidian-база) (*)

## Конвенция именования

`NN[letter]_имя_слоя.md`, где `NN` — номер слоя из таблицы ТЗ §5, `letter` —
буква под-слоя (только у слоя 4). Имя слоя — латиницей, snake_case,
описательное.

## Правила при добавлении нового слоя

- Один слой — один файл, не смешивать обязанности нескольких слоёв в одном
  промте (иначе теряется независимая проверяемость/логируемость, см. ТЗ §5.1).
- Обязательно секция **Запреты** — явно описывает, чего слой не должен делать
  (обычно: не выполнять работу соседних слоёв, не писать в vault напрямую в
  обход `08_obsidian_lint.md`, не придумывать факты, не молчать при низкой
  уверенности).
- Формат вывода — по возможности структурированный (список полей), чтобы
  следующий слой/инструмент мог его детерминированно распарсить.
- Обновить таблицу выше и таблицу в `ТЗ.md` §5 в одном PR.
