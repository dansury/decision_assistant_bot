# Decision Assistant

**Дневник в Telegram, который помнит вашу жизнь — и советует, опираясь на неё.**

Вы наговариваете голосовое по дороге со встречи. Через полгода бот напомнит,
чем закончилась прошлая такая сделка — до того, как вы согласитесь на новую.

➜ **[@decision_assistant_bot](https://t.me/decision_assistant_bot)** ·
`голос и текст` · `база — markdown в вашем Obsidian` · `self-hosted`

Бот персональный: отвечает владельцу и тем, кто внесён в
`TELEGRAM_ALLOWED_USERS`. Свой экземпляр поднимается одним контейнером —
[быстрый старт](#быстрый-старт).

## Зачем

Личный опыт не хранится в виде, пригодном для поиска: голосовые «себе»,
заметки в трёх приложениях, переписки, канал-дневник. Дневник помнит факты, но
не связывает их; чат-бот отвечает умно, но про вас не знает ничего.

Decision Assistant замыкает круг:

1. вы рассказываете — голосом, текстом, фото, документом, постом в канале;
2. бот раскладывает по базе: `Journal/`, `People/`, `Decisions/`;
3. вы приходите с сомнением — бот отвечает прогнозом на ваших прошлых случаях;
4. вы говорите исход — решение становится прецедентом.

Шаг 4 — то, чего нет у чат-ботов: обратная связь от реальности. Пока исход
неизвестен, случай помечен `status: open` и в доводы не идёт.

## Как это выглядит

> **Вы** *(голосовое, 14 секунд):* Думаю, не согласиться ли на предложение
> Марка по франшизе. Смущает, что опять всё быстро.
>
> **Бот:** Прогноз: скорее неудачное — значимый риск повторения паттерна спешки.
> Похожие случаи: `[[2025-03-11-вклад-в-кафе]]` (исход: неудача),
> `[[2024-09-02-подряд-без-договора]]` (исход: неудача). Что снизило бы риск:
> зафиксировать условия выхода до первого платежа.
> Записал в `Decisions/`, исход открыт.

Прогноз собирается конвейером: суть решения → факторы и риски → прецеденты →
взгляд оптимиста, пессимиста и реалиста → синтез. Числовых вероятностей бот не
выдаёт — это ложная точность ([`PRD.md`](./PRD.md) §4.4).

## Отличие от чат-бота

| | Чат-бот | Decision Assistant |
|---|---|---|
| Память | текущий диалог | всё, что вы когда-либо рассказали |
| Совет | «вообще, по интернету» | на **ваших** решениях и их исходах |
| Проверка | никакой | исход дописывается и меняет будущие прогнозы |
| Данные | чужое облако | markdown в вашем Obsidian, читается без бота |
| Люди | безымянный контекст | файл на человека, `[[ссылки]]`, backlinks |
| Цена | подписка | топ-1 бесплатной модели OpenRouter; платная — только на критичных слоях |

## Конвейер

Каждая запись проходит слои 0–11; у каждого свой промт в [`Promts/`](./Promts)
и своя модель — правится без пересборки образа.

`0` роутинг · `1` транскрибация · `2` персоны · `3` классификация ·
`4a–4f` консультант · `5–7` документы, фото, рукопись · `8` линт под
конвенции базы · `9` ответ и обратная связь · `10` импорт истории источника ·
`11` разбор zip-архива.

На выходе — `Journal/`, `People/`, `Decisions/`, `Documents/`, `Photos/`,
`Wiki/` в вашем Obsidian-vault.

## Ваши данные — ваши

- База — обычные markdown-файлы Obsidian на вашем томе (`VAULT_PATH`,
  по умолчанию `/opt/data/vault`). Выключите бота — база останется.
- Развёртывание своё: один контейнер на amvera или локально, ключи ваши.
- Один владелец: чужие сообщения игнорируются. Мультитенантность — не-цель.
- Без биометрии: «кто на фото» бот всегда спрашивает.
- Не медицинский и не финансовый советник: прогноз — рефлексия над вашей же
  историей.

## Кому это

| Подходит | Не подходит |
|---|---|
| Кто ведёт канал-дневник или шлёт заметки «себе» | Командам: бот на одного владельца |
| Кто принимает много решений с людьми и хочет видеть свои паттерны | Кому нужна база в чужом облаке «под ключ» |
| Кому важно владеть базой в открытом формате | Кто не готов держать свой контейнер и ключи |

# Техническая часть

## Быстрый старт

```bash
cp env.example .env          # TELEGRAM_BOT_TOKEN, OPENROUTER_API_KEY,
                             # YANDEX_CLOUD_API_KEY, YANDEX_CLOUD_FOLDER_ID
docker compose up --build    # long polling
```

Свой Telegram ID узнайте у [@userinfobot](https://t.me/userinfobot) и впишите
в `TELEGRAM_ALLOWED_USERS`.

Ключи: [@BotFather](https://t.me/BotFather) · https://openrouter.ai/keys ·
Yandex Cloud — сервисный аккаунт с ролью `ai.languageModels.user`
([доки](https://yandex.cloud/ru/docs/ai-studio/)).

## Деплой на amvera.ru

1. `git push` в проект amvera — сборка из `Dockerfile`, конфиг `amvera.yml`
   (том монтируется в `/opt/data`).
2. В сервисе → **«Переменные»** задайте секреты: `TELEGRAM_BOT_TOKEN`,
   `TELEGRAM_ALLOWED_USERS`, `OPENROUTER_API_KEY`, `LLM_MODEL`,
   `YANDEX_CLOUD_API_KEY`, `YANDEX_CLOUD_FOLDER_ID`.
3. Пересоберите сервис. Публичный порт не нужен — long polling.

## Из чего собрано

| Компонент | Роль |
|---|---|
| [hermes-agent](https://github.com/NousResearch/hermes-agent) | Ядро агента и Telegram-шлюз, LLM через OpenRouter. Базовый образ закреплён по digest (`config/hermes/base-image.env`) |
| [gbrain](https://github.com/garrytan/gbrain) | Долговременная память, семантический поиск. MCP-сервер, эмбеддинги — Yandex Cloud |
| [Grafify](https://github.com/LuaAccess/Grafify) | Граф знаний по коду. MCP-сервер + скилл `/graphify` |
| `tools/second-brain-mcp/` | Логика ассистента: персоны, vault, feedback, выбор модели, импорт истории. Промты слоёв `Promts/*.md` → `SOUL.md` |

```
Telegram ──> hermes-agent
               │ LLM   ──> OpenRouter (агент + суммаризатор)
               │ voice ──> Yandex SpeechKit (STT + TTS)
               │ MCP   ──> gbrain ──> Yandex Cloud (эмбеддинги)
               │ MCP   ──> Grafify (граф кода)
               └ MCP   ──> second-brain (персоны/vault/feedback)
```

Всё в одном контейнере на amvera, данные — в томе `/opt/data`.

### Внешние API

- **OpenRouter** — ответы и рассуждения агента (`OPENROUTER_API_KEY`,
  `LLM_MODEL`) и суммаризатор авто-сжатия диалога (`LLM_SUMMARY_MODEL`).
- **Yandex Cloud** — SpeechKit для голоса (STT/TTS как command-провайдеры
  hermes) и эмбеддинги gbrain. Одни ключи `YANDEX_CLOUD_API_KEY` +
  `YANDEX_CLOUD_FOLDER_ID`. YandexGPT можно включить как основной LLM
  (`LLM_PROVIDER=yandex`).

## Выбор модели

Провайдер и модель основного агента переключаются в Telegram командой
`/model` (встроена в hermes):

```
/model                                  открыть список моделей
/model anthropic/claude-opus-4.6        переключить модель
/model --provider yandex                переключиться на YandexGPT
```

Провайдер `yandex` регистрируется entrypoint-ом автоматически при заданных
ключах Yandex Cloud.

**Авто-роутинг по сложности** — плагин
[hermes-smart-model-routing](https://github.com/Waylish/hermes-smart-model-routing),
включён по умолчанию (`SMART_ROUTING_ENABLED=true`): короткая заметка → дешёвая
модель, рассуждение → сильная. Срабатывает до ручного `/model` и cost-флоу
слоя 9. Тиры — `SMART_ROUTING_*` в `env.example`; `cheap` = топ-1 бесплатная
модель OpenRouter.

**Каталог бесплатных моделей.** Источник истины — сам каталог OpenRouter
(модели с нулевой ценой), рейтинг [shir-man](https://shir-man.com/api/free-llm/top-models)
даёт порядок и квоты. Кэш на томе, обновление раз в 24 ч, fail-soft. MCP-инструменты:

| Инструмент | Что делает |
|---|---|
| `list_free_models` | Бесплатные модели; `modalities: ["image"]` — только с картинками |
| `list_models_by_price` | Весь каталог по возрастанию цены, бесплатные первыми |
| `recommend_model_for_layer` | Некритичные слои → бесплатная, критичные → платная. Политика — `config/layer_policy.json` |
| `estimate_model_cost` | Оценка вызова в USD и ₽ (курс — `config/fx.json`) |

Критичность слоёв правится в `config/layer_policy.json` без правки кода:
`criticality`, `expected_out_tokens`, `requires` (`image` / `file`).

Что чем настраивается:

| Процесс | Настройка |
|---|---|
| Основной агент | `/model` в Telegram или `LLM_MODEL` / `LLM_PROVIDER` |
| Слои конвейера | `config/layer_policy.json` + `recommend_model_for_layer` |
| Суммаризатор | `LLM_SUMMARY_MODEL` / `LLM_SUMMARY_PROVIDER` |
| Эмбеддинги (gbrain) | `GBRAIN_EMBEDDING_PROVIDER` + `YANDEX_EMBEDDING_MODEL` |
| Голос | `YANDEX_STT_LANG`, `YANDEX_TTS_VOICE`, `VOICE_AUTO_TTS` |

## Импорт истории канала

Telegram Bot API истории не отдаёт, поэтому (ТЗ §4.1, слой 10):

- публичный канал/группа — с веб-превью `https://t.me/s/<username>`
  (`import_chat_history`, пагинация `?before=`);
- приватный канал/«Избранное» — из JSON-выгрузки Telegram Desktop
  (`import_chat_history_file`), о которой бот просит сам.

Записи ложатся в `Journal/` датами оригинальных сообщений со ссылкой на
оригинал; дубли не создаются, догрузка идёт по `since_id` из
`history_import_status`.

## Эксплуатация

**Vault:** `scripts/vault.sh status | backup | reset`.

**Память:** скажите боту «забудь, что …» (вызовет `forget_fact` у gbrain) или
`scripts/memory.sh status | clear | forget <id> | search <запрос>`
(`make memory-status` / `make memory-clear`). `clear` делает полный wipe с
переинициализацией. gbrain инициализируется сам в `GBRAIN_HOME`
(`/opt/data/gbrain`, PGLite — внешняя БД не нужна) и переживает перезапуски.

**Граф кода:** граф репозитория закоммичен в `graphify-out/` и зашит в образ,
так что бот отвечает на вопросы о собственной структуре
(`GRAFIFY_ENABLED=true`). Свой проект — постройте граф и укажите
`GRAFIFY_GRAPH_PATH`. Для разработки установлен скилл `/graphify` и хуки
`.claude/settings.json`. Обновить: `pip install "graphifyy[mcp]"` → `make graph`.

**Версия ядра hermes** закреплена по digest в `config/hermes/base-image.env`
(`FROM` в `Dockerfile` — её отражение, расхождение ловит job `verify-pin`):

```bash
make hermes-status     # что закреплено и что вышло в апстриме
make hermes-check      # есть ли новая версия (код 10 = есть)
make hermes-update     # закрепить свежую
make hermes-rollback   # вернуть предыдущую
```

`.github/workflows/hermes-update.yml` раз в сутки проверяет апстрим, собирает
образ на новой версии, прогоняет смоук-тесты и только тогда открывает PR.
Обновление доезжает мерджем PR, откат — его revert-ом.

**Снимки состояния.** В образ зашита версия ядра (`/opt/second_brain/BASE_IMAGE`);
при смене версии entrypoint снимает состояние тома до того, как новая версия
его тронет. Снимок не удался — контейнер не стартует
(`STATE_BACKUP_REQUIRED=false` снимает ограничение).

```bash
make snapshots            # список снимков
make snapshot             # снять сейчас
make restore ID=<id>      # восстановить (сначала снимет pre-restore)
```

Бота перед восстановлением остановите. Полный откат обновления — две операции:
`make hermes-rollback` + передеплой для версии ядра, `state-snapshot.sh restore last`
для данных. Данные (`/opt/data`) пересборку образа переживают; `SOUL.md` и
`config.yaml` собираются заново при каждом старте.

## Сборка и проверка

Образ собирает CI (`.github/workflows/build.yml`) на каждый пуш/PR, amvera при
деплое, локально — `docker compose up --build`. В песочнице разработки доступ к
Docker Hub закрыт egress-политикой, поэтому образ собирается в CI, а не здесь.

Перед продом: прогнать `docker compose up --build` с реальными ключами,
убедиться, что бот отвечает в Telegram текстом и голосом и что в логах
поднялись MCP-серверы, затем деплоить.

Второй репозиторий, [hermes-agent-skills](https://github.com/zad111ak-ai/hermes-agent-skills),
намеренно не подключён: его мета-скиллы уже покрыты стеком — сжатие контекста →
`auxiliary.compression`, QA и смена модели по фидбеку → слои `Promts/*`,
долговременная память → gbrain.
